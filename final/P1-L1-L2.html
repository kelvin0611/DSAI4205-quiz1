二、L1 Big Data · L2 Parallelism、HDFS、Dask

一分鐘重點
  • Big Data 用 6Vs 形容：Volume（多）、Velocity（快）、Variety（雜）、Veracity（準唔準）、Value（有冇用）、Variability（會變）。MCQ 會俾情境叫你揀邊個 V。
  • 單部電腦唔夠用，就 scale out：將數據切細（partition）分俾好多部機一齊做，再合併結果（divide and conquer）。
  • HDFS：檔案切成固定大細嘅 block，每個 block 存 3 份，寫一次讀好多次。
  • Dask：平行版 NumPy／Pandas，將 array 切成 chunks，lazy，.compute() 先計。

Divide and conquer：平行處理嘅基本諗法

一句講完

將數據切成好多份（partition），每個 worker 處理一份，最後將 sub-result 合併。

圖解 易錯

Worker 加倍唔代表快一倍：要考慮溝通成本、數據搬運同等最慢嗰個 worker。

HDFS：分散式檔案系統

一句講完

將一個大檔案切成固定大細嘅 block，每個 block 喺唔同機器存 3 份，檔案寫一次、讀好多次。

圖解
特點意思點解
Fixed-size partitioning檔案切成一樣大嘅 block方便分俾唔同機器平行處理
3-way replication每個 block 存 3 份Fault tolerance：機壞咗仲有副本
Write-once read-many寫完唔改，只係讀為 batch 分析設計，唔使處理同時改寫嘅問題

Dask：chunks 同 block algorithm

一句講完

Dask 將大 array 切成細 chunks，每塊各自計，再合併；係 lazy 嘅，.compute() 先真正計。

圖解：4×4 array 用 chunks=(2,2) 計 sum（Exam Review slide 12–13） 例子：數 chunk

da.ones((10000, 12000), chunks=(5000, 4000))：第一個維度 10000/5000 = 2，第二個 12000/4000 = 3，共 \(2 \times 3 = 6\) 個 chunk。

易錯

chunks 係每塊嘅形狀，唔係「分幾多塊」。太細（例如 1）overhead 大；太大放唔落 memory；建議每塊 100 MB 至 1 GB。rechunk 好貴。

L2 · Scale up vs Scale out

  • Moore's law：transistor 數量大約每 18–24 個月翻一倍。但因為 quantum tunneling 同散熱，單個 CPU 唔可能再每 18 個月快一倍。2005 年 Herb Sutter：“The Free Lunch Is Over”。Transistor 仍然增加，用嚟加多啲 core。
  • 處理大數據三條路：Data reduction（feature selection、dimensionality reduction、compression）；Efficient algorithm & data structure（indexing、tree、hashmap、graph）；將工作分派畀多個 processor／worker。
  • Multi-core：同一粒 chip 上有多個 core，用 shared memory（同一個地址喺所有 core 指向同一份數據），每個 core 有自己嘅 local state。
  • 挑戰：worker 加倍，throughput 唔會加倍，因為協調有 overhead（5 人 team vs 30 人 team）。
  • Bulk operations / Data parallelism：同一個指令、多份數據（same instructions, multiple data items），例如 df[df['A'] > 1] 可以每個 core 處理唔同行。

L2 · Sharding vs Replication、HDFS

Sharding／PartitioningReplication
做咩將數據集切細，分佈喺多個 node喺唔同 node 存同一份數據嘅多個副本
目的平行處理Fault tolerance（redundancy）、讀得快（scalability）
代價／細節Vertical = 按 table／column 切；Horizontal = 同一個 table 嘅 row 分去唔同 node要 synchronization 保持所有副本一致（consistency）
  • Horizontal partition 啱做：filtering df[df['A'] > 1]、projection df[['A','B']]、apply。唔啱：groupby('A').count()，要先重新排數據，令相同 A 嘅 row 喺同一個 partition。
  • 點樣分：Range（一段 key 對應一個 core ID）或者 Hashing：n 個 core，key k 放去 h(k) % n。
  • HDFS（最常用分散式檔案系統）：fixed-size partitioning、3-way replication、write-once read-many。

L2 · Dask

Dask 係 open-source Python library，令你可以平行運算，將 NumPy、Pandas 由一部機擴展到幾千 core 嘅 cluster。點解用：familiar interface（API 似 NumPy/Pandas，改少少 code）、scalability、flexibility（dask.delayed）、diagnostic tools（live dashboard 搵 bottleneck）。第一條規則：唔係乜都啱用；平行運算有 overhead，數據細就唔值。數據塞唔落 memory 或者要平行計先用。

Collection層級對應建立方法
Dask ArrayHigh-levelnumpy.arraydask.array.from_array
Dask DataFrameHigh-levelpandas DataFramedask.dataframe.read_csv、dd.from_pandas(df, npartitions=10)
Dask BagHigh-levelPython list（unstructured）dask.bag.from_sequence([1,2,3])
delayedLow-level將任何 function 變 lazy、平行執行（似 loop 入面 call function）@dask.delayed，之後 .compute()
futuresLow-level似 delayed 但可以即時並行執行（似背景 process）—
  • Scheduler：將工作切成 segment → 送去唔同 worker → 協調；worker 計完將結果送返 scheduler。Client(n_workers=2) 喺自己部機開 2 個 worker。
  • Dask 係 lazy：dask_data.mean() 只起 task graph（約 3.5 ms），.compute() 先真正計（約 30 ms），結果變返 NumPy。
  • Task graph：每個 node = 一個 task，每條線 = task 之間嘅依賴。數據大嘅時候用 high-level graph（.dask.visualize()）。
  • chunks 參數係「每塊嘅形狀」，唔係塊數。chunks=1 即係每塊一個元素。
  • Chunk size：太細 → overhead 太大；太大 → 塞唔落 memory。建議 100 MB 至 1 GB。rechunk 好貴（rechunk(10,10) 要 7 分鐘）。
  • Dask DataFrame = 好多個 pandas DataFrame（partitions），lazy 載入、多 core 平行處理，可以一次讀多個 file（'data/*.csv'）。Pandas 經驗法則：memory 要係數據 5–10 倍。
  • Dask DataFrame 啱做：element-wise（df.x + df.y）、row filtering（df[df.x > 0]）、aggregation（df.x.max()）、drop duplicates。唔啱：要 shuffle 或 re-index 嘅操作，例如 set_index。

四、MapReduce 概念同答題模板

一分鐘重點
  • MapReduce 三步：Map（每筆記錄出 (key, value)）→ Shuffle（framework 自動按 key 分組）→ Reduce（每個 key 合併 values）。
  • 寫 pseudocode 一定要寫明每一步嘅 input 同 output (key, value)。
  • Filter 喺 Map 做；計數 emit (key, 1)、Reduce 加總；收集名單 Reduce 輸出 list。

MapReduce 成個流程

流程圖：word count

MapReduce 係 Google 喺 2004 年發明，第一個廣泛使用嘅分散式大數據框架。三大賣點：簡單嘅程式模型（只寫 map 同 reduce）、用平價硬件大規模擴展、內置 fault tolerance。數據模型：一個 file 就係一袋 (key, value) pair，input 同 output 都係 (key, value)，output 嘅 key 可有可無。

步驟做咩
1 · Map由每個 record／文件抽取資料，輸出 (key, value)
2 · Shuffle & Sort將 record 喺唔同機器之間搬，按 key 分組
3 · Reduceaggregate、summarize、filter 或 transform
4 · Write寫出結果。成個框架唔變，只係因應題目改 map 同 reduce function

課堂 word count 例子（slide 11）

map(String key, String value):          // key: document name, value: document contents
    for each word w in value:
        emitIntermediate(w, 1)

reduce(String key, Iterator values):    // key: a word, values: a list of counts
    sum = 0
    for each v in values:
        sum += v
    emit(key, sum)
Q1(a) 答題模板（4 步）
  1. 問自己：最後要「按咩分組」？答案就係 key。題目講 “in each department” → key = department；“for each word” → key = word。
  2. MAP：parse input → 如有條件就喺呢度 filter → emit(key, value)。
  3. Shuffle 唔使寫：框架自動變成 (key, [v1, v2, …])。可以喺 comment 寫低 reducer 會收到乜，示範你明。
  4. REDUCE：for each v in values → 加總／揀最大／去重複 → emit(key, result)。

考試要求「specify input and output (key, value) pairs」嘅話，喺每個 function 上面用 comment 寫低 Input 同 Output 嘅格式同例子。

MapReduce 嘅問題（點解要有 Spark）

  • 所有嘢都要用 mapper 同 reducer 表達，好 rigid（唔可以淨係有 mapper），複雜 query 要串好多個 MapReduce job。
  • 所有中間結果都寫落 disk（為咗 fault tolerance）。
  • 唔同 iteration／phase 之間只可以靠 shared storage 傳數據。
  • 因為 replication 同 disk I/O，所以慢。理想係經 memory 傳。
MapReduceSpark
中間結果寫落 disk（HDFS）放 memory（RDD，可以 cache）
程式模型得 map + reduce 兩步好多 transformation：map、filter、join、groupByKey…
Fault tolerance靠 replication + disk靠 lineage 重算失咗嘅 partition
最適合一次過嘅 batch jobiterative、互動分析、streaming

COMP4434 舊卷 · 同類 MapReduce pseudocode

每個城市有幾多個人擁有多過 2 架車

每行：(resident name, number-of-cars, city)，例如 (Alex, 2, HK)。

睇答案
function MAP(key = line offset, value = "name, cars, city"):
    name, cars, city = parse(value)
    if cars > 2:
        emit(city, 1)                 # output: (city, 1)

function REDUCE(key = city, values = [1, 1, ...]):
    emit(city, sum(values))           # output: (city, count)

Filter 放喺 Map 度做，唔符合嘅記錄直接唔 emit，shuffle 嘅數據會少好多。

每個部門有幾多個人工高過 $50,000 嘅 Analyst

每行：(employee_id, department, job_role, salary)。

睇答案
function MAP(key, value = "id, dept, role, salary"):
    id, dept, role, salary = parse(value)
    if role == "Analyst" and salary > 50000:
        emit(dept, 1)

function REDUCE(key = dept, values):
    emit(dept, sum(values))

兩個條件都要喺 Map 檢查。如果題目話 salary 有 “$55,000” 呢類格式，要先去走 $ 同逗號先轉數字。

題 1：每個部門人工高過 25,000 嘅畢業生人數

A large table is distributed across multiple files. Each row is (student_name, department, salary), e.g. (Bob, Computing, 30,000). Determine, in each department, the total number of graduated students whose salary is more than 25,000 in their first job. (1) Provide concise pseudo-code for the Map worker, specifying the input and output (key, value) pairs. (2) Same for the Reduce worker.

睇答案
// (1) Map worker
// Input : key = row id (or file offset), value = (student_name, department, salary)
// Output: key = department, value = 1          e.g. (Computing, 1)
function MAP(row_id, row):
    (name, dept, salary) = parse(row)
    if salary > 25000:
        emit(dept, 1)

// (2) Reduce worker
// Input : key = department, value = list of 1s  e.g. (Computing, [1, 1])
// Output: key = department, value = total count  e.g. (Computing, 2)
function REDUCE(dept, counts):
    total = 0
    for each c in counts:
        total = total + c
    emit(dept, total)

題 2：一個好大嘅整數 file

Design MapReduce algorithms to take a very large file of integers and produce as output: (a) the largest integer; (b) the average of all the integers; (c) the same set of integers, but with each integer appearing only once; (d) the count of the number of distinct integers.

睇答案
// (a) Largest integer：全部用同一個 key，送去同一個 reducer
function MAP(key, n):
    emit("max", n)
function REDUCE(k, numbers):
    m = -infinity
    for each n in numbers:
        if n > m: m = n
    emit("max", m)

// (b) Average：value 要帶 (sum, count)
function MAP(key, n):
    emit("avg", (n, 1))
function REDUCE(k, pairs):
    total = 0; count = 0
    for each (s, c) in pairs:
        total = total + s
        count = count + c
    emit("avg", total / count)

// (c) Distinct：數字本身做 key，shuffle 自動將重複嘅 group 埋一齊
function MAP(key, n):
    emit(n, null)
function REDUCE(n, values):
    emit(n, null)                 // 每個 key 只會 emit 一次

// (d) Count distinct：要兩個 job
// Job 1 = (c)；Job 2：
function MAP(n, null):
    emit("count", 1)
function REDUCE(k, ones):
    emit("count", sum(ones))
  • (a) 得一個 key → 只有一個 reducer 做嘢，會變 bottleneck。改良：每個 map task 先計自己嗰份嘅最大值，先 emit 一個數（書入面叫 combiner）。
  • (b) 如果 mapper 先自己計平均，一定要送 (sum, count)，唔可以送平均值：[1,2,3] 平均 2、[10] 平均 10，「平均嘅平均」= 6，但真平均 = 16 ÷ 4 = 4。
  • (d) 一個 MapReduce job 做唔晒，要串兩個 job，呢個正正係 L3 講 MapReduce「too rigid」嘅例子。

題 3：Document frequency：每個字出現喺幾多份文件

Same input as the inverted index (D1 || the cat sat on the mat …). Output each word with the number of documents that contain it, e.g. the: 3, cat: 1.

睇答案
function MAP(doc_id, document_text):
    words = split(trim(document_text), " ")
    for each word in words:
        emit(word, doc_id)

function REDUCE(word, doc_ids_list):          // e.g. ("the", [D1, D1, D3, D4])
    unique_docs = removeDuplicates(doc_ids_list) // [D1, D3, D4]
    emit(word, length(unique_docs))             // ("the", 3)

結果：the 3、brown 3、quick 2、fox 2、sat 2、on 2、mat 2、cat 1、a 1、jumps 1。

陷阱

如果照 word count 咁 emit (word, 1) 再 sum，“the” 會得 4（D1 有兩個 the），咁係數「出現次數」，唔係「文件數」。

Each input record is (line_no, "date,city,temperature"), e.g. (1, "2025-07-01,HongKong,33"). Output the maximum temperature of each city.

Each row is (user_id, movie_id, rating). Output (movie_id, average rating).

睇答案

題 6：Positional inverted index（記埋位置）

Extend the inverted index so each word maps to the documents and the positions where it appears, e.g. the: [(D1, [0, 4]), (D3, [0]), (D4, [2])].

睇答案
function MAP(doc_id, document_text):
    words = split(trim(document_text), " ")
    for i from 0 to length(words) - 1:
        emit(words[i], (doc_id, i))            // value 係 (文件, 位置)

function REDUCE(word, postings):               // e.g. ("the", [(D1,0), (D1,4), (D3,0), (D4,2)])
    result = empty map
    for each (doc, pos) in postings:
        result[doc].append(pos)
    emit(word, sorted list of (doc, positions))   // ("the", [(D1,[0,4]), (D3,[0]), (D4,[2])])

呢題唔可以去重複：D1 兩個 “the” 位置唔同（0 同 4），兩個都要保留。

七、MCQ

八、短答題

5. Inverted index MapReduce 入面，shuffle 做咗咩？點解 reducer 要去重複？

The shuffle phase collects all mapper outputs and groups them by key, sending all pairs with the same word to the same reducer as (word, [doc_ids]). It only groups; it does not remove duplicates. If a word appears twice in one document (e.g. “the” in D1), D1 appears twice in the list, so the reducer must remove duplicates before emitting the result.

7. Scale up vs scale out；點解大數據用 scale out？

Scale up (vertical) upgrades one machine with a faster CPU or more memory; scale out (horizontal) adds more machines or workers and distributes the work. Single-CPU clock speeds can no longer keep doubling because of physical limits (heat, quantum tunnelling), and one machine's memory is limited, so big data systems such as Hadoop, Dask and Spark scale out. Coordination overhead means doubling the workers does not double the throughput.

8. Sharding（partitioning）同 replication 有咩分別？

Sharding splits a dataset into smaller subsets, horizontally (rows) or vertically (columns or tables), stored on different nodes so they can be processed in parallel. Replication stores multiple copies of the same data on different nodes for fault tolerance and faster reads (HDFS keeps 3 copies), at the cost of keeping the replicas consistent.

九、常見疑問

Q：Map 嘅 input key 係乜？
通常係檔案入面嘅位置（line offset）或者 document id，好多題目唔重要，可以寫 “key: document id / line number”。重點係講清楚 value 係乜。
Q：Shuffle 要唔要自己寫 code？
唔使。Shuffle 係 framework 自動做：按 key group 埋，送去同一個 reducer。畫圖時要畫出嚟，寫 pseudocode 就唔使。
Q：Reducer 收到嘅 values 有冇排序？
冇保證。Inverted index 要排序或者去重複，就要喺 reducer 自己做（sorted(set(...))）。
Q：Mutual friends 點解要 sort pair？
A 嘅 mapper 會出 (B,C)，B 嘅 mapper 可能出 (C,B)。唔排序就會變兩個 key，shuffle 唔會 group 埋。
Q：6Vs 要背到幾熟？
老師講長題唔考背書，MCQ 會俾情境叫你揀邊個 V。記住每個 V 嘅「關鍵字」就得（見上面個表嘅第三欄）。
