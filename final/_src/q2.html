Practice Quiz 2 · Q1 Spark DataFrame and UDF

An existing RDD raw_sensor_rdd has tuples (sensor_id: Int, location: String, reading_value: Double, raw_timestamp: String). Convert it into a DataFrame df_sensors. You must not use .toDF(); define a strict schema with StructType and StructField.

from pyspark.sql.types import StructType, StructField, IntegerType, StringType, DoubleType

schema = StructType([

df_sensors = spark.createDataFrame(raw_sensor_rdd, schema)
df_sensors.printSchema()

Q1(b) · 寫 UDF 做情感分類

Practice Quiz 2 · Q1 第二部分（老師堂上逐步講過）

df_reviews has review_id (Integer), customer_id (Integer), feedback_text (String). (1) Write analyze_sentiment(text): “Positive” if it contains great / love / excellent, “Negative” if bad / broken / waste (case-insensitive), otherwise “Neutral”; return “Unknown” if text is None or empty. (2) Register it as sentiment_udf with the correct Spark SQL return type. (3) Create df_segmented with all original columns plus sentiment_category.

from pyspark.sql import SparkSession
from pyspark.sql.functions import udf, col
from pyspark.sql.types import StringType

# 1. Define the standard Python logic with edge-case handling
def analyze_sentiment(text):
    if text is None or text.strip() == "":            # edge case 先處理
        return "Unknown"
    t = text.lower()                                  # case-insensitive
    if any(w in t for w in ["great", "love", "excellent"]):
        return "Positive"
    if any(w in t for w in ["bad", "broken", "waste"]):
        return "Negative"
    return "Neutral"

# 2. Register the function as a PySpark UDF explicitly declaring StringType
sentiment_udf = udf(analyze_sentiment, StringType())

# 3. Apply it to the DataFrame using withColumn
df_segmented = df_reviews.withColumn("sentiment_category", sentiment_udf(col("feedback_text")))

# Displaying output
df_segmented.show(truncate=False)
feedback_text 例子sentiment_category
"I LOVE this phone"Positive
"Arrived broken, total waste"Negative
"It is okay"Neutral
None 或 " "Unknown

以上 Python 邏輯已經逐個例子跑過核對。

易失分位
  • 先檢查 None：text.lower() 遇到 None 會出錯，所以 edge case 要放第一行。
  • 一定要寫 return type：udf(analyze_sentiment, StringType())。題目寫明 “explicitly declare the correct Spark SQL return data type”。
  • 保留所有原本 column → 用 withColumn，唔好用淨係揀一個 column 嘅 select。
  • UDF 要應用喺 column：sentiment_udf(col("feedback_text"))、sentiment_udf(df_reviews.feedback_text) 或 sentiment_udf("feedback_text") 都得。
  • 同時有正面同負面字（例如 “great price but bad battery”）會因為次序先判 Positive，可以喺答案註明你嘅優先次序。

Q2(a) · BPE：將字串減到啱啱 10 個 token

Practice Quiz 2 · Q2(a) · 老師話係去年 Sem 2 期考原題

Demonstrate the iterative steps (such as in Byte Pair Encoding) required to reduce "apple pen apple pen pineapple pen" to exactly 10 tokens. You may use <_> to represent spaces or word boundaries.

做法：每個字拆成字母，字尾加 <_>。字頻係 apple ×2、pen ×3、pineapple ×1。每一步搵出現最多次嘅相鄰 pair 合併，總 token 數 = 每個字嘅 token 數 × 出現次數。

步驟合併次數apple ×2pen ×3pineapple ×1總 token
0（起點）—a p p l e <_>p e n <_>p i n e a p p l e <_>2×6 + 3×4 + 10 = 34
1a + p → ap3ap p l e <_>p e n <_>p i n e ap p l e <_>31
2ap + p → app3app l e <_>p e n <_>p i n e app l e <_>28
3app + l → appl3appl e <_>p e n <_>p i n e appl e <_>25
4appl + e → apple3apple <_>p e n <_>p i n e apple <_>22
5apple + <_> → apple<_>3apple<_>p e n <_>p i n e apple<_>19
6p + e → pe3apple<_>pe n <_>p i n e apple<_>16
7pe + n → pen3apple<_>pen <_>p i n e apple<_>13
8pen + <_> → pen<_>3apple<_>pen<_>p i n e apple<_>10

最後 10 個 token：apple<_> | pen<_> | apple<_> | pen<_> | p | i | n | e | apple<_> | pen<_>。新增嘅 vocabulary：ap、app、appl、apple、apple<_>、pe、pen、pen<_>。

  • 每一步有好多 pair 同樣出現 3 次（例如 p p、l e、e n）。打和揀邊個都得，最緊要寫清楚每步合併邊個 pair、出現幾多次、合併後總 token 數。上表用「最先出現嘅 pair」打和。
  • 點解 pineapple 冇變成一個 token：「p i n e」只出現 1 次，頻率低，未輪到合併就已經夠 10 個。呢個正正示範 subword 點樣處理罕見字：由常見嘅 subword（apple）加字母砌出嚟，就算 pineapple 從來冇見過都可以表示（OOV 問題）。

已經用程式逐步模擬核對過每一步嘅 token 數。

1. 冇語意（semantic）：每個字係獨立維度，近義字當完全唔同如果 Doc 4 係 “Kelvin enjoys soccer”，soccer 同 football 意思一樣，但 TF-IDF 向量完全冇重疊，cosine = 0。
2. 冇字序同上下文（bag of words）“Kelvin enjoys playing football” 同 “football enjoys playing Kelvin” 會得到一模一樣嘅向量。“don't like” 同 “like” 分唔到。

4. 高維、稀疏向量長度 = vocabulary 大小；文件一多，維度好大而大部分係 0（例如 Doc 2 五個維度得一個非零）。
5. 處理唔到新字（OOV）Query 入面有 “basketball”，vocabulary 冇呢個字，就冇維度表示佢。

Q3 · Levenshtein distance：“Teh” 同 “The”

(i) Fill the 5×5 Levenshtein DP table for “Teh” and “The”. (ii) Show all possible operations to transform “Te” → “Th” using DP[2][3], DP[2][2], DP[3][2]. (iii) Compute the Levenshtein distance for “Teh hero save” vs “The hero saves”.

(i) 5×5 = 第 0 行／列寫字母，第 1 行／列係空字串 “”。跟 lecture 嘅寫法，source（Teh）放上面，target（The）放左邊。

idx01234

規則：DP[i][j] = min( DP[i-1][j-1] + (字母唔同 ? 1 : 0), DP[i-1][j] + 1, DP[i][j-1] + 1 )。第一行／列 = 0, 1, 2, 3（全部 insert 或者 delete）。Teh → The 距離 = 2（右下角）：e→h、h→e 兩次 substitution。Levenshtein 唔識「對調」，所以 swap 要計 2。

(ii) 目標格係 DP[3][3]（source “Te” → target “Th”）。三個 subproblem：

由邊格嚟Subproblem值再加一步總數
DP[2][2]（對角）“T” → “T”0Substitute e → h0 + 1 = 1 ✓ 最少
DP[2][3]（上面）“Te” → “T”（delete e）1Insert h1 + 1 = 2
DP[3][2]（左邊）“T” → “Th”（insert h）1Delete e1 + 1 = 2

所以 DP[3][3] = min(1, 2, 2) = 1。反方向 “Th” → “Te” 都一樣：用 DP[2][2] substitute h → e，1 步。Levenshtein 係對稱嘅，table 轉置之後數字一樣。

(iii) “Teh hero save” → “The hero saves”：“Teh” → “The” 要 2 步，“hero” 一樣，“save” → “saves” insert s 1 步，總距離 = 3（已用 DP 程式核對）。

L4 Exploring Hive, Shark and SparkSQL · T04

Hive → Shark → Spark SQL 同 DataFrame

Hive

  • Facebook 開發，將 structure／schema 加落 HDFS 數據，將 HiveQL 編譯成 MapReduce jobs。當年 Facebook 超過 90% MapReduce job 由 Hive 產生。
  • HiveQL 係 limited 版 SQL：DDL（create／drop／alter table、database、view）、DML（insert、select、update、delete、load data）、query（SELECT / WHERE / GROUP BY / HAVING / ORDER BY / LIMIT、各種 JOIN）、functions、PARTITIONED BY、CLUSTERED BY（bucketing）。
  • LOAD DATA LOCAL INPATH ... OVERWRITE INTO TABLE t：LOCAL = 由本機讀；冇 LOCAL = 由 HDFS 讀；OVERWRITE = 刪走舊數據。Partitioned table 要寫 PARTITION (ds='2025-09-16')。
Hive 數據模型三層喺 HDFS 點樣存用途
Table每個 table 一個 directory，數據 serialize 成 file 放入去Typed columns（int、float、string、boolean），支援 map 類型
PartitionTable directory 入面嘅 sub-directory決定數據分佈，例如按日期 range-partition
BucketPartition directory 入面嘅 file（分 n 個 bucket 就 n 個 file）用 hash 再細分，方便 sampling 同 join

Hive 架構同編譯步驟

  • Metastore：存 table 嘅 schema、位置、partition 資料
  • Driver：管理 HiveQL query 嘅生命週期
  • Compiler：HiveQL → parse tree → plan
  • Execution engine：將 plan 變成 MapReduce 喺 Hadoop 執行

Parser（語法、parse tree）→ Semantic analysis（檢查 table／column／type）→ Logical plan generator → Optimizer → Physical plan generator（DAG of MapReduce jobs）

Hive 特點同限制

  • Petabyte 級 data warehouse，基於 MapReduce + HDFS；係 OLAP，唔係 OLTP
  • Fault-tolerant、scale-out、支援 nested data、UDF、custom mapper／reducer、SerDe
  • 限制：高 latency（細 query 都要幾分鐘）、唔啱互動式分析、多 join 嘅複雜 query 慢、冇內置 ML／iterative algorithm

Shark

  • 動機：data warehouse 有好強嘅 temporal locality（最近用過嘅數據好快會再用），Facebook 90% query 可以喺 main memory 完成。大部分 query 只睇細嘅數據 window（例如每日 log），唔使將 petabyte 塞入 memory。
  • 做法：保留 Hive 嘅 scalability 同 extensibility，將 Hive 嘅 MapReduce physical plan／execution engine 換成 Spark RDD，加 cache manager 同改 optimizer。
Shark 嘅新功能重點
In-memory table cachingCREATE TABLE mytable_cached AS SELECT ...，底層用 RDD.cache()
Data co-partitioning相同 join key 嘅 record 放同一個 partition，之後 join 更快
Cost-based optimizer估算唔同執行策略嘅成本，揀 join 次序
Partial DAG Execution（PDE）Run-time 收集統計（partition 大細同 record 數、heavy hitters、近似 histogram），worker 送去 master，動態改 plan：揀 shuffle join 定 broadcast join、決定 reducer 數量、處理 skew
Columnar memory store按 column 存：SELECT AVG(age) 只讀 age 一欄，減少 I/O；壓縮好（dictionary encoding、run-length encoding）；少 object、對 JVM garbage collection 友好

Shark 唔支援：hash-based bucketing、不同 partition 用唔同 input format、合併細 output file、自動 map-side join。點解 2014 年停止：只可以 query Hive metastore 入面嘅外部數據（唔可以 query Spark 程式自己處理緊嘅 RDD）；要經 SQL string 調用，易出錯；沿用為 MapReduce 設計嘅 Hive optimizer，難擴展。→ 轉做 Spark SQL。

Spark SQL 同 DataFrame

Spark SQL（2014，Spark 1.0 開始）直接建喺 Spark core 上面，加咗兩樣嘢：DataFrame API 同 Catalyst optimizer（將 logical plan 變成高效 physical plan）。

語言學層次研究咩例子

Subword tokenization（BPE）

點解要：解決 unknown word（OOV）。例如訓練數據有 “foot” 同 “ball” 但冇 “football”，或者有 low、new、newer 但冇 lower。Subword 可以減細 vocabulary，靈感來自 information theory 嘅數據壓縮。

三個演算法做咩
Token learner由 training corpus 學 vocabulary：① 全部拆成單字母 ② 搵最常出現嘅相鄰 pair ③ 合併並加入 vocabulary（大小 +1）④ 重複直至夠數或者冇 pair 再夠頻率
Token segmenter（encoder）用學到嘅 vocabulary（同 merge 次序）切新句子
Token merger（decoder）將 token 序列砌返原本句子

L6 Part 2 · Text embedding · T06

Word embedding：Word2Vec、SGNS、GloVe

字嘅意思

  • Lemma：break, breaks, broke, broken, breaking 共用 lemma “break”
  • Synonymy：couch／sofa、car／automobile（完全同義好少）
  • Similarity vs relatedness：couch／sofa 相似；couch／pillow 只係有關聯
  • Antonymy：只喺一個特徵相反：long／short、rise／fall

Semantic feature space

  • 用特徵（cuteness、size；gender、age、royalty）表示字，用 Euclidean distance 比較
  • Analogy：king − man + woman：[1,8,8] − [1,7,0] + [9,7,0] = [9,8,8] ≈ queen
  • 手動設計特徵唔可行 → 由大量文字自動學，typical 300 維
  • Distributional hypothesis：喺相似上下文出現嘅字意思相似。Harris（1954）：oculist 同 eye-doctor 出現喺差唔多嘅環境；Firth（1957）：“You shall know a word by the company it keeps.”
  • One-hot 嘅問題：cat 同 feline 嘅 one-hot cosine = 0，捉唔到相似。Embedding 將每個字變成 continuous dense vector，意思近嘅字喺空間入面距離近。

Skip-gram vs CBOW（Word2Vec, Mikolov 2013）

Skip-gramCBOW
Input → OutputCenter word → 每個 context word所有 context words → center word
假設① 每個 window 係 i.i.d. 樣本 ② 俾定 center，context words 條件獨立 ③ 唔理 context 位置（前 1 位、後 2 位一樣處理）① window i.i.d. ② 每個 context word 用同一方法處理，唔理位置
LossJ(θ) = −Σₜ Σ₋ₘ≤ⱼ≤ₘ, ⱼ≠0 log P(wₜ₊ⱼ | wₜ)（negative log likelihood）J(θ) = −Σₜ log P(wₜ | wₜ₋ₘ, …, wₜ₊ₘ)
模型P(o|c) = exp(u_o·v_c) / Σₖ exp(u_k·v_c)（softmax）用 (1/2m)(v_o1 + … + v_o2m) 平均再同 u_c 做 dot product + softmax
每個字兩個向量用 center 向量 V 做 embedding；context 向量 U 只喺訓練用通常用 context 向量做 embedding
T06 Keras 實作—Embedding(vocab, dim) → Lambda(mean) → Dense(vocab, softmax)，loss = categorical cross-entropy，optimizer = Adam；PAD = index 0、UNK = 1

Lecture 數字例子：one-hot × W 等於揀出 W 嘅某一行（lookup table），例如 “passes” → v_c = [0.1, 0.2, 0.7]；乘 W′ 得 logits，softmax 後 loss = −log(0.155065) = 0.8095。CBOW example：W 兩行 (0.38, 0.42) 同 (−0.11, 0.1) 取平均 → h = (0.135, 0.26)，softmax 後 P(sit) = 0.2626，loss = −log(0.2626)。

SGNS 同 GloVe

Skip-gram with Negative Sampling

  • 問題：softmax 分母要加總成個 vocabulary V（可以好大），好慢
  • 做法：變成 binary logistic regression：(center, 真 context) → y = 1；(center, 隨機抽嘅字) → y = 0
  • P(y=1|c,o) = σ(u_o·v_c) = 1/(1+e^(−u_o·v_c))
  • 點解要 negative：淨係有 positive，模型只要將 dot product 調到好大就「作弊」令 loss 變細
  • 每個 positive 抽 k 個 negative：J = −log σ(u_o·v_c) − Σ log(1 − σ(u_k·v_c))

GloVe（Stanford）

  • Global Vectors：先建 co-occurrence count matrix（V × V，好高維）
  • 用 matrix factorization 分解成低維 embedding
  • 好處：好快；捉到 word2vec（只睇 batch 入面嘅 window）睇唔到嘅 global statistics
  • 但一般 word2vec 效果較好

MCQ 同短答解釋部分

概念短答

Quiz 1 Section B Q1 係兩條各 5 分嘅概念題（“Define lazy evaluation… Use Dask to justify”）。答題格式：一句定義 → 用課程工具解釋點運作 → 一個具體例子。第 9–11 題特登用呢個格式寫。

1. 點解 DataFrame 通常比 RDD 快？

A DataFrame has a schema (named, typed columns), so Spark knows the structure of the data and the operations are declarative. The Catalyst optimizer can rewrite the logical plan (predicate pushdown, constant folding, join reordering, runtime code generation) and data is stored in a compact columnar binary format. RDD transformations take arbitrary lambdas that are black boxes to Spark, and the data are opaque Java/Python objects, so little optimization is possible.

2. 點解 Hive 慢？Shark 點改善？

Hive compiles HiveQL into MapReduce jobs, which write intermediate results to disk, so even small queries take minutes and it is unsuitable for interactive or iterative analytics. Shark keeps HiveQL compatibility but replaces the MapReduce execution engine with Spark RDDs, exploiting temporal locality with in-memory table caching, columnar memory storage, data co-partitioning and Partial DAG Execution that re-optimizes the plan at run time.

3. 點解 Shark 被 Spark SQL 取代？

Shark could only query external data in the Hive metastore, not data inside Spark programs; it had to be invoked through SQL strings, which is error-prone; and it inherited Hive's optimizer designed for MapReduce, which was hard to extend. Spark SQL adds the DataFrame API that mixes SQL with programmatic code and the extensible Catalyst optimizer.

4. 點解要 subword tokenization？

Word-level models cannot handle unknown (out-of-vocabulary) words, e.g. “football” when only “foot” and “ball” were seen, and a word vocabulary becomes huge with many rare words. Subword methods such as BPE build a vocabulary of frequent character sequences by repeatedly merging the most frequent adjacent pair, so any new word can be represented as a sequence of known subwords while keeping the vocabulary small.

5. Stemming 同 lemmatization 有咩分別？

Stemming crudely chops affixes with rules (e.g. Porter's), and the result may not be a real word (computing → comput, companies → compani). Lemmatization uses vocabulary and part-of-speech information to return the dictionary form (am, are, is → be; ran → run), which is more accurate but slower.

6. Skip-gram 同 CBOW 有咩分別？

Skip-gram uses the centre word to predict each context word in the window; CBOW uses the (averaged) context words to predict the centre word. Both assume windows are independent samples and ignore the position of context words. Skip-gram uses the centre-word vectors as embeddings; CBOW commonly uses the context vectors.

7. 點解要 negative sampling？

The softmax in standard skip-gram normalizes over the whole vocabulary V, which is very expensive when V is large. SGNS turns the task into binary logistic regression with a sigmoid: real (centre, context) pairs are labelled 1 and k randomly sampled words are labelled 0. Negative samples are needed because with only positive pairs the model could trivially make every dot product large.

8. GloVe 同 Word2Vec 有咩分別？

Word2Vec learns from local context windows. GloVe first builds a global word–word co-occurrence count matrix (V × V) over the whole corpus and factorizes it into low-dimensional vectors, so it is fast and captures global statistics that window-based word2vec misses, although word2vec often works better in practice.

9. (5 marks) Define lazy evaluation in Spark DataFrames. Use an example to justify your answer.

Lazy evaluation means operations are not executed when they are written; Spark only records them as a logical plan and runs them when an output operation needs a result. For example, df.filter(df.quantity > 20).withColumn("revenue", df.quantity * df.price) reads no data; Spark only builds a plan with a filter and a new column. When .show() or .count() is called, the Catalyst optimizer optimizes the whole plan (e.g. pushes the filter down so fewer rows are processed) and then executes it on the workers.

10. (5 marks) What is a user-defined function (UDF) in Spark SQL, and why must its return type be declared?

A UDF wraps a normal Python function so it can be applied to DataFrame columns when built-in Spark SQL functions are not enough, e.g. classifying unstructured review text. It has two parts, the function and the output data type, as in sentiment_udf = udf(analyze_sentiment, StringType()), applied with withColumn("sentiment_category", sentiment_udf(col("feedback_text"))). Because a DataFrame has a schema, Spark must know the type of the new column in advance; if the declared type does not match the returned values, the column becomes null. A UDF is a black box to the Catalyst optimizer, so built-in functions such as when are preferred when they can do the job.

11. (5 marks) Explain the out-of-vocabulary (OOV) problem and how Byte Pair Encoding addresses it, with an example.

Word-level models only have vectors for words seen in training, so a new word such as “football” (when only “foot” and “ball” were seen) is unknown. BPE starts from single characters and repeatedly merges the most frequent adjacent pair into a new token, building a vocabulary of frequent subwords. A new word is then segmented into known subwords, e.g. “pineapple” → p, i, n, e, apple, so every word can be represented while the vocabulary stays small.
