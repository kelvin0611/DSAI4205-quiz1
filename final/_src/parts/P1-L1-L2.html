二、L1 Big Data · L2 Parallelism、HDFS、Dask

一分鐘重點
  • Big Data 用 6Vs 形容：Volume（多）、Velocity（快）、Variety（雜）、Veracity（準唔準）、Value（有冇用）、Variability（會變）。MCQ 會俾情境叫你揀邊個 V。
  • 單部電腦唔夠用，就 scale out：將數據切細（partition）分俾好多部機一齊做，再合併結果（divide and conquer）。
  • HDFS：檔案切成固定大細嘅 block，每個 block 存 3 份，寫一次讀好多次。
  • Dask：平行版 NumPy／Pandas，將 array 切成 chunks，lazy，.compute() 先計。

Divide and conquer：平行處理嘅基本諗法

一句講完

將數據切成好多份（partition），每個 worker 處理一份，最後將 sub-result 合併。

圖解 易錯

Worker 加倍唔代表快一倍：要考慮溝通成本、數據搬運同等最慢嗰個 worker。

HDFS：分散式檔案系統

一句講完

將一個大檔案切成固定大細嘅 block，每個 block 喺唔同機器存 3 份，檔案寫一次、讀好多次。

圖解
特點意思點解
Fixed-size partitioning檔案切成一樣大嘅 block方便分俾唔同機器平行處理
3-way replication每個 block 存 3 份Fault tolerance：機壞咗仲有副本
Write-once read-many寫完唔改，只係讀為 batch 分析設計，唔使處理同時改寫嘅問題

Dask：chunks 同 block algorithm

一句講完

Dask 將大 array 切成細 chunks，每塊各自計，再合併；係 lazy 嘅，.compute() 先真正計。

圖解：4×4 array 用 chunks=(2,2) 計 sum（Exam Review slide 12–13） 例子：數 chunk

da.ones((10000, 12000), chunks=(5000, 4000))：第一個維度 10000/5000 = 2，第二個 12000/4000 = 3，共 \(2 \times 3 = 6\) 個 chunk。

易錯

chunks 係每塊嘅形狀，唔係「分幾多塊」。太細（例如 1）overhead 大；太大放唔落 memory；建議每塊 100 MB 至 1 GB。rechunk 好貴。

Dask chunks 補充（Exam Review 重點）

寫法意思例子
chunks=1000每個維度每塊 1000(10000, 12000) → 10 × 12 = 120 塊
chunks=(5000, 4000)每塊形狀 5000 × 4000(10000, 12000) → 2 × 3 = 6 塊
chunks={0: 1000, 1: 2000}用 dict 逐個維度指定同 (1000, 2000) 一樣
chunks=((1000,1000,…),(3000,…))逐塊寫明大細可以唔平均
易錯chunks 係每塊嘅形狀，唔係「分幾多塊」。chunks=1 即係每塊得 1 個元素，會慢到死。建議每塊 100 MB 至 1 GB；太細 overhead 大，太大放唔落 memory。rechunk 好貴。

Block algorithm 例子：4×4 array 用 chunks=(2,2) 分 4 塊，sum() 先計每塊（14、22、46、54），再加埋 = 136。.visualize() 畫出 task graph：node = task，線 = dependency。Dask 係 lazy，.compute() 先真正計。

COMP4434 舊卷 · 同類 MapReduce pseudocode

每個城市有幾多個人擁有多過 2 架車

每行：(resident name, number-of-cars, city)，例如 (Alex, 2, HK)。

睇答案
function MAP(key = line offset, value = "name, cars, city"):
    name, cars, city = parse(value)
    if cars > 2:
        emit(city, 1)                 # output: (city, 1)

function REDUCE(key = city, values = [1, 1, ...]):
    emit(city, sum(values))           # output: (city, count)

Filter 放喺 Map 度做，唔符合嘅記錄直接唔 emit，shuffle 嘅數據會少好多。

每個部門有幾多個人工高過 $50,000 嘅 Analyst

每行：(employee_id, department, job_role, salary)。

睇答案
function MAP(key, value = "id, dept, role, salary"):
    id, dept, role, salary = parse(value)
    if role == "Analyst" and salary > 50000:
        emit(dept, 1)

function REDUCE(key = dept, values):
    emit(dept, sum(values))

兩個條件都要喺 Map 檢查。如果題目話 salary 有 “$55,000” 呢類格式，要先去走 $ 同逗號先轉數字。

九、常見疑問

Q：Map 嘅 input key 係乜？
通常係檔案入面嘅位置（line offset）或者 document id，好多題目唔重要，可以寫 “key: document id / line number”。重點係講清楚 value 係乜。
Q：Shuffle 要唔要自己寫 code？
唔使。Shuffle 係 framework 自動做：按 key group 埋，送去同一個 reducer。畫圖時要畫出嚟，寫 pseudocode 就唔使。
Q：Reducer 收到嘅 values 有冇排序？
冇保證。Inverted index 要排序或者去重複，就要喺 reducer 自己做（sorted(set(...))）。
Q：Mutual friends 點解要 sort pair？
A 嘅 mapper 會出 (B,C)，B 嘅 mapper 可能出 (C,B)。唔排序就會變兩個 key，shuffle 唔會 group 埋。
Q：6Vs 要背到幾熟？
老師講長題唔考背書，MCQ 會俾情境叫你揀邊個 V。記住每個 V 嘅「關鍵字」就得（見上面個表嘅第三欄）。
