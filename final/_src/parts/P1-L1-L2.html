二、L1 Big Data · L2 Parallelism、HDFS、Dask

一分鐘重點
  • Big Data 用 6Vs 形容：Volume（多）、Velocity（快）、Variety（雜）、Veracity（準唔準）、Value（有冇用）、Variability（會變）。MCQ 會俾情境叫你揀邊個 V。
  • 單部電腦唔夠用，就 scale out：將數據切細（partition）分俾好多部機一齊做，再合併結果（divide and conquer）。
  • HDFS：檔案切成固定大細嘅 block（128 MB），每個 block 存 3 份，寫一次讀好多次。
  • 處理 big data 三條路：data reduction、efficient algorithm／data structure、分工俾多個 worker。
  • Dask：平行版 NumPy／Pandas，將 array 切成 chunks，lazy，.compute() 先計；dask.compute(a, b) 共享中間結果，persist() 留喺 memory。

Big Data 嘅四層 components（L1 p.31）

一句講完

由下而上：儲存 → 分散式計算 → library → 分析／演算法。上層用下層。

圖解 易錯

HDFS 係儲存層，唔係計算層；MapReduce、Dask、RDD 係計算層；NetworkX 係 library；PageRank（link analysis）係最頂嘅分析層。

處理 big data 嘅三條路（L2 p.6）

一句講完

CPU clock speed 已經升唔上，單線程快唔到幾多，所以只有三條路：減數據、用好啲嘅演算法／資料結構、分工俾多個 worker。呢科主要講第三條。

路做法例子
① Data reduction令數據細啲Feature selection、dimensionality reduction、data compression
② Efficient algorithm & data structure同樣數據，搵得快啲Indexing、tree、hash map／hash table、graph
③ Allocate workload to multiple workers平行處理（divide and conquer）MapReduce、Spark、Dask
易錯

Dimensionality reduction 屬於 data reduction，唔係「efficient algorithm」；hash table 屬於 data structure。

Divide and conquer：平行處理嘅基本諗法

一句講完

將數據切成好多份（partition），每個 worker 處理一份，最後將 sub-result 合併。

圖解 易錯

Worker 加倍唔代表快一倍：要考慮溝通成本、數據搬運同等最慢嗰個 worker。

HDFS：分散式檔案系統

一句講完

將一個大檔案切成固定大細嘅 block（default 128 MB，Exam Review p.10），每個 block 喺唔同機器存 3 份，檔案寫一次、讀好多次。

圖解
特點意思點解
Fixed-size partitioning檔案切成一樣大嘅 block方便分俾唔同機器平行處理
3-way replication每個 block 存 3 份Fault tolerance：機壞咗仲有副本
Write-once read-many寫完唔改，只係讀為 batch 分析設計，唔使處理同時改寫嘅問題

Dask：chunks 同 block algorithm

一句講完

Dask 將大 array 切成細 chunks，每塊各自計，再合併；係 lazy 嘅，.compute() 先真正計。

圖解：4×4 array 用 chunks=(2,2) 計 sum（Exam Review slide 12–13） 例子：數 chunk

da.ones((10000, 12000), chunks=(5000, 4000))：第一個維度 10000/5000 = 2，第二個 12000/4000 = 3，共 \(2 \times 3 = 6\) 個 chunk。

易錯

chunks 係每塊嘅形狀，唔係「分幾多塊」。太細（例如 1）overhead 大；太大放唔落 memory；建議每塊 100 MB 至 1 GB。rechunk 好貴。

寫法意思例子
chunks=1000每個維度每塊 1000(10000, 12000) → 10 × 12 = 120 塊
chunks=(5000, 4000)每塊形狀 5000 × 4000(10000, 12000) → 2 × 3 = 6 塊

易錯chunks 係每塊嘅形狀，唔係「分幾多塊」。chunks=1 即係每塊得 1 個元素，會慢到死。建議每塊 100 MB 至 1 GB；太細 overhead 大，太大放唔落 memory。rechunk 好貴。

Block algorithm 例子：4×4 array 用 chunks=(2,2) 分 4 塊，sum() 先計每塊（14、22、46、54），再加埋 = 136。.visualize() 畫出 task graph：node = task，線 = dependency。Dask 係 lazy，.compute() 先真正計。

Task graph 長咩樣：low-level vs high-level（L2 p.30–31）

一句講完

Dask 每個操作都變成 task graph：node = 一個 task，箭咀 = 依賴。.visualize() 畫每個 chunk嘅 task（low-level）；.dask.visualize() 只畫每一層操作（high-level）。

圖解：4 個 chunk 嘅 sum()
點解要兩種

Low-level 睇到真正有幾多個 task 可以平行（4 個 sum 互不相干，可以同時跑）；high-level 睇成條 pipeline 有咩步驟，chunk 多到幾十萬都仲睇得明。

易錯

考試叫你畫 task graph，畫 low-level：每個 chunk 一個 node，同一層嘅 node 冇箭咀連住（可以平行），最後先匯合（aggregate）。

Lazy 嘅證據：點解一句咁快？（L2 p.36、p.55–57）

一句講完

Dask 未 .compute() 之前只係砌 task graph，所以「計」得好快；.compute() 先真係做嘢。

例子寫法Wall time
Array meanNumPy data.mean()105 ms（真計）
Array meanDask dask_data.mean()3.51 ms（淨係砌 graph）
LinkedIn 5 個 table mergepandas merge(…)6.95 s
LinkedIn mergeDask，未 compute（npartitions=100）50.4 ms（淨係砌 graph）
LinkedIn mergeDask .compute()4.06 s（真計，平行之後快過 pandas）
易錯

3.51 ms 唔代表 Dask 快 30 倍，因為佢根本未計。公平比較要用 .compute() 之後嘅時間：LinkedIn 例子係 6.95 s vs 4.06 s。

dask.delayed：將普通 Python function 變平行（L2 p.41–44）

一句講完

Function 加 @dask.delayed，call 佢就唔會即刻跑，只係加一個 node 入 task graph；.compute() 先跑，而且冇依賴嘅 task 會同時跑。

@dask.delayed
def inc(x):    return x + 1
@dask.delayed
def double(x): return x * 2
@dask.delayed
def add(x, y): return x + y

a = inc(5)        # 未計
b = double(5)     # 未計
c = add(a, b)     # c = Delayed('add-…')
c.compute()       # 6 + 10 = 16
圖解 Loop 版（p.43–44） 
output = []
for i in range(100):
    x = random.random()
    c = add(inc(x), double(x))
    output.append(c)
total = dask.delayed(sum)(output)   # sum 都要 delayed
total.compute()

100 組 inc／double／add 互不相干，可以分晒俾 worker；最後 sum 匯合。Built-in function（例如 sum）唔可以加 decorator，所以寫 dask.delayed(sum)(output)。

每個 worker 幾多 thread（L2 p.44） $$\text{threads} = \max\!\left(1,\; \left\lfloor \frac{\text{cores}}{n_{\text{workers}}} \right\rfloor\right)$$

threads = 每個 worker 嘅 thread 數；cores = 部機總共幾多 CPU core。

例如 8 核、Client(n_workers=2) ⇒ 每個 worker 4 條 thread；3 核、4 個 worker ⇒ ⌊0.75⌋ = 0，但最少 1。

COMP4434 舊卷 · 同類 MapReduce pseudocode

每個城市有幾多個人擁有多過 2 架車

每行：(resident name, number-of-cars, city)，例如 (Alex, 2, HK)。

睇答案
function MAP(key = line offset, value = "name, cars, city"):
    name, cars, city = parse(value)
    if cars > 2:
        emit(city, 1)                 # output: (city, 1)

function REDUCE(key = city, values = [1, 1, ...]):
    emit(city, sum(values))           # output: (city, count)

Filter 放喺 Map 度做，唔符合嘅記錄直接唔 emit，shuffle 嘅數據會少好多。

每個部門有幾多個人工高過 $50,000 嘅 Analyst

每行：(employee_id, department, job_role, salary)。

睇答案
function MAP(key, value = "id, dept, role, salary"):
    id, dept, role, salary = parse(value)
    if role == "Analyst" and salary > 50000:
        emit(dept, 1)

function REDUCE(key = dept, values):
    emit(dept, sum(values))

兩個條件都要喺 Map 檢查。如果題目話 salary 有 “$55,000” 呢類格式，要先去走 $ 同逗號先轉數字。

九、常見疑問

Q：Map 嘅 input key 係乜？
通常係檔案入面嘅位置（line offset）或者 document id，好多題目唔重要，可以寫 “key: document id / line number”。重點係講清楚 value 係乜。
Q：Shuffle 要唔要自己寫 code？
唔使。Shuffle 係 framework 自動做：按 key group 埋，送去同一個 reducer。畫圖時要畫出嚟，寫 pseudocode 就唔使。
Q：Reducer 收到嘅 values 有冇排序？
冇保證。Inverted index 要排序或者去重複，就要喺 reducer 自己做（sorted(set(...))）。
Q：Mutual friends 點解要 sort pair？
A 嘅 mapper 會出 (B,C)，B 嘅 mapper 可能出 (C,B)。唔排序就會變兩個 key，shuffle 唔會 group 埋。
Q：Dask 幾時先真係計？
.compute()、len()、.head()、.tail()。其他操作（filter、groupby、mean）只係加 node 入 task graph。
Q：persist() 同 dask.compute(a, b) 有咩分別？
dask.compute(a, b) 係同一次計算入面共享中間步驟；persist() 係將結果留喺 memory，之後幾次 compute 都可以重用。
Q：T2 TODO 10 multiplier 填 0.6 定 1.60934？
