二、Spark 核心概念

一分鐘重點
  • RDD = 分散喺好多部機、唔可以改（immutable）嘅數據集合；壞咗靠 lineage 重新計。
  • Transformation（map、filter、flatMap、reduceByKey…）係 lazy，只係記低計劃；Action（collect、count、show、save）先真正執行。
  • 一變一用 map，一變多用 flatMap；加總用 reduceByKey，收集名單用 groupByKey。

Lazy evaluation：transformation 寫計劃，action 先開工

一句講完

Transformation 唔會即刻計，只係喺 memory 起一個 operator DAG；去到 action 先由頭到尾一次過執行。

圖解 點解要 lazy

等齊成個計劃先執行，Spark 可以合併步驟（pipelining）、避免計冇用嘅嘢；而且記低 lineage，有 partition 壞咗就照計劃重新計返嗰份。

易錯

MCQ 問「邊一行先真正執行」：搵第一個 action（collect、count、take、show、saveAsTextFile、write）。

map vs flatMap

一句講完

map：一個 element 變一個；flatMap：一個 element 變零至多個，再攤平成一個 RDD。

圖解
考試點揀

Mutual friends 每個 user 產生好多個 pair、inverted index 每份文件產生好多個 (word, doc)、PageRank 每頁產生好多個貢獻：全部用 flatMap。

reduceByKey vs groupByKey

一句講完

兩個都會按 key shuffle；reduceByKey 喺每個 partition 先合併一次再送，groupByKey 將所有 value 原封不動送過網絡。

三、RDD 操作速查

{{SEC:q1:ops}}

Pair RDD 再加四個：mapValues、flatMapValues、countByKey、countByValue

一句講完

頭兩個係 transformation，只郁 value、key 唔變；後兩個係 action，即刻計，返回 Python dict（defaultdict），唔係 RDD。

Operator類型輸入 → 輸出
mapValues(lambda x: [x, x*10])Transformation(a, 1) → (a, [1, 10])：一個 element 變一個
flatMapValues(lambda x: [x, x*10])Transformation(a, 1) → (a, 1)、(a, 10)：list 攤平，每個 value 配返同一個 key
countByKey()Action → dict數每個 key 出現幾多次
countByValue()Action → dict數每個成個 element（成個 tuple）出現幾多次
圖解：mapValues vs flatMapValues（T4 4.1–4.2，mtcars）
例子：countByKey vs countByValue（T4 4.3）

carData = [(Mazda, 2018), (Mazda, 2019), (Ferrari, 2019), (Porsche, 2019)]

Call結果
carData.countByKey(){Mazda: 2, Ferrari: 1, Porsche: 1}
carData.countByValue(){(Mazda, 2018): 1, (Mazda, 2019): 1, (Ferrari, 2019): 1, (Porsche, 2019): 1}
carData.map(lambda x: x[1]).countByValue(){2018: 1, 2019: 3}（呢個先係「每年幾多架」）
例子：汽車 = TF／DF 模板（T4 4.4）

(2018, 'Mazda Ferrari')、(2019, 'Porsche Ford Mazda')、(2020, 'Ferrari Honda Tesla Mazda')：

  • flatMapValues(lambda x: x).countByValue() → 每個 (year, brand) 出現幾次 = term frequency
  • flatMapValues(lambda x: x).distinct().map(lambda x: (x[1], x[0])).countByKey() → Mazda 3、Ferrari 2、其餘 1 = document frequency
  • count() → 3 = 文件數

將「年份」換做「文件」、「牌子」換做「字」，就係 T5 TF-IDF 嘅 code。完整 drill（fill-in + 25 個輸出）喺 P3 四、RDD 手計 TF-IDF。

易錯
  • Notebook 註解話 countByValue 係「每年出咗幾多架車」，係誤導：佢數成個 tuple，四個 tuple 各 1。
  • Slide／notebook 寫 flatMapValues「3 input will have 1 output」，係講錯：每個 input 變 2 個 output，3 個 input 就 6 個 output。
  • mapValues／flatMapValues 放喺 多欄 Row 上面（例如 mtcars 12 欄）：Spark 只當 x[0] 係 key、x[1] 係 value，其餘欄全部丟走。所以 mtcars 結果只有 (車款, [mpg, mpg×10])。
  • countByKey／countByValue 係 action，後面唔可以再 .map()；要繼續用 RDD 就改用 map((k, 1)).reduceByKey(add)。

四、Hive → Shark → Spark SQL、DataFrame

一分鐘重點
  • 點解要 Hive：MapReduce 只有兩段，複雜 query（例如每個 category top-2）要串幾個 job，join／sort 全部手寫，太 low-level。
  • Hive 將 SQL 變 MapReduce（慢）；Shark 用 Spark + memory（快）；Spark SQL 加 DataFrame + Catalyst optimizer。
  • DataFrame = 有 schema 嘅分散式 table；schema 用 StructType([StructField(name, type, nullable)])。
  • UDF = 自己寫嘅 Python function：udf(f, ReturnType)，return type 錯就出 null。

DataFrame + UDF 嘅資料流

圖解：Quiz 2 真卷 compliance UDF
df_transactions
id | country | memo
1 | HK | "urgent bitcoin gift"
withColumn + UDF
audit_result =
{risk_score: 80,
flagged_terms: [bitcoin, urgent, gift]}
select + "struct.field"
audit_score = 80
triggered_keywords = [...]
  1. 寫 Python function，回傳值嘅結構要同 schema 一樣（dict key = StructField 名）。
  2. 用 StructType 寫 return type；list 用 ArrayType(StringType())。
  3. udf(function, schema) 註冊。
  4. withColumn("新欄名", my_udf(col("a"), col("b")))，column 次序要跟 function 參數。
  5. 用 col("struct.field").alias("新名") 攤平。

同一題三種寫法：每個 category 嘅 top-2 URL（Exam Review p.42–47、L4 p.6–13）

題目

兩個 table：Visits（User, URL, Time）同 UrlInfo（URL, Category, PageRank）。搵每個 category 最多人睇嘅 2 個 URL。

UserURLTime
Amyamazon.com8:00
Amyfacebook.com10:00
Amytwitter.com10:05
Fredamazon.com12:00
Kennethespn.com21:00
Janicetwitter.com08:44
URLCategoryPR
amazon.comEcommerce0.9
facebook.comSocial Network0.8
twitter.comSocial Network0.7
espn.comSports0.6
點解要串兩個 job

MapReduce 每個 job 只有 Map 同 Reduce 兩段，一次 shuffle 只可以按一種 key 分組。呢題要先按 URL 分組（join + 數 visit），再按 category 分組（排名），所以要兩個 job，第一個 job 嘅輸出寫落 HDFS 再俾第二個 job 讀。

寫法 ①：兩階段 MapReduce pseudocode

# ---------- Job 1：join Visits 同 UrlInfo，數每個 URL 嘅 visit ----------
Mapper1(user, url, time):            emit(url, ("visit", 1))
Mapper2(url, category, pagerank):    emit(url, ("info", category))
Reducer1(url, values):
    visit_count = 0; category = null
    for v in values:
        if v.type == "visit": visit_count += v.count
        if v.type == "info":  category = v.category
    if category != null and visit_count > 0:
        emit(category, (url, visit_count))

# ---------- Job 2：每個 category 排名，取頭 2 ----------
Mapper3(category, (url, count)):     emit(category, (url, count))
Reducer2(category, values):
    L = sort(values, by count, descending)
    for rank, (url, count) in enumerate(L[0:2], start=1):
        emit((category, rank), (url, count))

寫法 ②：點解話「MapReduce API too low-level」

上面兩個 job，join、select、projection、aggregate（count）、sort、distinct 全部要自己逐行寫。程式員其實只係想講「join 完 group by 再排名」。所以 Facebook 整咗 Hive：用 SQL 寫，Hive 自動 compile 成 MapReduce job（Facebook 超過 90% 嘅 MapReduce job 由 Hive 生成）。

寫法 ③：HiveQL 一句搞掂

SELECT category, url, visit_count, rank FROM (
    SELECT u.category, v.url, COUNT(*) AS visit_count,
           RANK() OVER (PARTITION BY u.category
                        ORDER BY COUNT(*) DESC, v.url ASC) AS rank
    FROM Visits v JOIN URLInfo u ON v.url = u.url
    GROUP BY u.category, v.url
) ranked
WHERE rank <= 2
ORDER BY category, rank;
SQL 部分對應 MapReduce
JOIN … ON v.url = u.url + GROUP BY + COUNT(*)Job 1（按 URL shuffle，join + 數）
RANK() OVER (PARTITION BY category ORDER BY … DESC)Job 2（按 category shuffle，排序）
WHERE rank <= 2Job 2 Reducer 嘅「取頭 2」

輸出同 MapReduce 版一樣：Ecommerce 1 amazon.com 2；Social Network 1 twitter.com 2、2 facebook.com 1；Sports 1 espn.com 1（已用 SQLite 跑過）。

易錯
  • Reduce 1 要分清兩種 value（"visit" 同 "info"），所以 mapper 要加 tag；冇 tag 就唔知邊個係 category。
  • Job 2 嘅 output key 係 (category, rank)，唔係 category。
  • PARTITION BY = 每個 category 各自排名；唔寫就變咗全部 URL 一齊排。
  • Slide 嘅 UrlInfo 表有兩個筆誤：twitter.com 嘅 category 印咗 “facebook.com”（Mapper 2 例子係 Social Network）、espn.com PageRank 一處寫 0.9 一處寫 0.6。唔影響答案（呢題唔用 PageRank）。

用 PySpark RDD 建 inverted index

documents.txt 每行好似 D1 || the cat sat on the mat。輸出 word: [doc ids]，字按字母排，doc id 唔重複。

睇答案
from pyspark.sql import SparkSession
ss = SparkSession.builder.appName("InvertedIndex").master("local[4]").getOrCreate()
spark = ss.sparkContext

lines = spark.textFile("documents.txt")
docs = lines.map(lambda l: l.split("||")) \
            .map(lambda p: (p[0].strip(), p[1].strip().split()))   # (doc_id, [words])

index = docs.flatMap(lambda d: [(w, d[0]) for w in set(d[1])]) \
            .groupByKey() \
            .mapValues(lambda ids: sorted(set(ids))) \
            .sortByKey()

for word, ids in index.collect():
    print(f"{word}: {ids}")
步驟點解
split("||") + strip()分開 doc id 同內容，去走空格
flatMap + set(d[1])一份文件產生好多個 (word, doc)；set 令 D1 嘅兩個 “the” 只出一次
groupByKey()同一個字嘅 doc id 收埋一齊
mapValues(sorted(set()))轉做 list、去重、排序
sortByKey()字按字母排，同 expected output 一樣

都可以用 reduceByKey(lambda a, b: a + b)，map 嗰陣 value 寫 [doc_id]。已用 Python 模擬核對：the → ['D1', 'D3', 'D4']、brown → ['D2', 'D3', 'D4']。

Quiz 2 真卷 Q1(b) · 12 分

Compliance risk UDF：回傳 nested struct 再 flatten

df_transactions 有 transaction_id、account_country、memo_text。Function 回傳 dict：risk_score（含 crypto／bitcoin／mixer +50；urgent／gift／loan 而且國家唔係 US +30；最多 100；memo 空就 −1）同 flagged_terms（搵到嘅字）。

睇答案
from pyspark.sql.functions import udf, col
from pyspark.sql.types import StructType, StructField, StringType, IntegerType, ArrayType

def evaluate_compliance_risk(memo, country):
    if memo is None or str(memo).strip() == "":
        return {"risk_score": -1, "flagged_terms": []}
    memo_lower = str(memo).lower()
    country_upper = str(country).upper() if country else ""
    crypto_terms = {"crypto", "bitcoin", "mixer"}
    urgency_terms = {"urgent", "gift", "loan"}
    found_terms = [t for t in crypto_terms | urgency_terms if t in memo_lower]
    score = 0
    if any(t in memo_lower for t in crypto_terms):
        score += 50
    if any(t in memo_lower for t in urgency_terms) and country_upper != "US":
        score += 30
    score = min(score, 100)
    return {"risk_score": score, "flagged_terms": found_terms}

compliance_schema = StructType([
    StructField("risk_score", IntegerType(), False),
    StructField("flagged_terms", ArrayType(StringType()), False)
])

compliance_udf = udf(evaluate_compliance_risk, compliance_schema)

df_temp = df_transactions.withColumn(
    "audit_result", compliance_udf(col("memo_text"), col("account_country")))

df_audited = df_temp.select(
    col("transaction_id"), col("account_country"), col("memo_text"),
    col("audit_result.risk_score").alias("audit_score"),
    col("audit_result.flagged_terms").alias("triggered_keywords"))
  • Dict 嘅 key 一定要同 StructField 名一樣，否則對唔上，出 null。
  • ArrayType(StringType()) = 裝字串嘅 list。
  • 傳 column 嘅次序要跟 function 參數：先 memo，後 country。
  • 用 "struct.field" 攞出 nested 欄位，再 .alias() 改名。

十、常見疑問

Q：RDD 同 DataFrame 有咩分別？
RDD 係最底層嘅分散式 collection，冇 schema，Spark 睇唔到你 lambda 入面做咩，所以冇得優化。DataFrame 有 schema（column 名同 type），Catalyst optimizer 可以自動優化，通常快啲。
Q：SparkSession 同 SparkContext 點分？
SparkContext（題目通常叫 spark 或者 sc）係 RDD 嘅入口；SparkSession 係 DataFrame／SQL 嘅入口，入面包住一個 SparkContext（ss.sparkContext）。2025s1 卷寫 spark = ss.sparkContext，所以嗰張卷 spark.textFile 係 RDD。
Q：groupByKey 同 reduceByKey 點揀？
要「收集名單」用 groupByKey；要「加總／計數／搵最大」用 reduceByKey，因為佢會先喺每個 partition 合併，shuffle 少好多。
Q：col 係咪改名？
唔係。col("x") 係「揀出 x 呢個 column」；改名用 .alias()；withColumn 第一個參數係新 column 嘅名。
Q：countByKey 同 reduceByKey 有咩分別？
結果一樣係「每個 key 幾多次」，但 countByKey 係 action，即刻返回 Python dict 去 driver；map(lambda x: (x[0], 1)).reduceByKey(add) 係 transformation，結果仲係 RDD，可以再 join（T5 TF-IDF 就係咁做）。
Q：Top-2 per category 考 pseudocode 要寫幾多？
兩個 job 各寫 Map 同 Reduce，寫清楚 emit 乜 key、乜 value；Job 1 mapper 要加 "visit"／"info" tag；Job 2 reducer sort desc 取頭 2，emit ((category, rank), (URL, count))。
Q：唔識 list comprehension 點算？
用普通 for loop 加 append 一樣得分，例如 mutual friends 嘅雙重 loop。
Q：UDF return type 寫錯會點？
唔會報錯，個 column 會變 null。所以 schema／return type 一定要同實際回傳嘅嘢夾。
