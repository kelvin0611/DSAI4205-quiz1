RQ1 · MapReduce and Spark：Mutual friends

Input：A → B,C,D；B → A,C,D,E；C → A,B,D,E；D → A,B,C；E → B,C。Mapper 要將 pair 按字母排序。

核心諗法（Combinatorial pair）：如果 A 嘅朋友有 B、C、D，咁 A 就係 (B,C)、(B,D)、(C,D) 每一對嘅共同朋友。所以 mapper 將每個 user 嘅朋友 list 兩兩配對，value 係 user 自己。

攞分位Map 階段最少畫 2–3 個 mapper，寫明 output 係 ((friend1, friend2), user)；Shuffle 要寫「group by key」；Reduce 最少寫 3 對嘅答案。pair 一定要排序，否則 (B,A) 同 (A,B) 會變兩個 key。
(b) Pseudocode
function map(user, friend_list):
    for i in 0 .. len(friend_list)-1:
        for j in i+1 .. len(friend_list)-1:
            pair = sort(friend_list[i], friend_list[j])
            emit(pair, user)

function reducer(pair, user_list):
    emit(pair, list(user_list))

Reducer 收到嘅 user_list 就係「同時有呢兩個朋友嘅人」，即係佢哋嘅共同朋友。

RQ3 · Text Embedding

(a) Define word embedding，用例子說明。(b) 兩份文件用 Word2Vec 學 vector，講兩個可能問題。

睇答案

(a) Word embedding 係將每個字變成一個低維、dense 嘅實數向量（例如 300 維），令意思相近或者用法相近嘅字，喺向量空間入面距離近。目的係俾 model 用數字理解字義，取代 one-hot 呢種又長又 sparse、又睇唔到相似度嘅表示法。

例子：cos(“cat”, “dog”) 高過 cos(“cat”, “car”)；vector(“king”) − vector(“man”) + vector(“woman”) ≈ vector(“queen”)，表示「性別」呢個關係變成向量入面一個方向。

(b) 可能問題

  1. 一字多義（polysemy）：“book” 喺 Document 1 係動詞「訂枱」，喺 Document 2 係 “close the book” 嘅名詞片語，但 Word2Vec 每個字只有一個固定 vector，兩個意思會撈埋一齊。
  2. 反義詞變相似：“increased” 同 “decreased” 出現喺一模一樣嘅 context（“The company's profits ___ significantly compared to…”），Word2Vec 只睇 context，所以會學到幾乎一樣嘅 vector，雖然意思相反。
  3. （另一個都得）語料太細：得兩句，co-occurrence 太少，vector 唔可靠；而且冇見過嘅字（OOV，例如串錯嘅 “unearning”）冇 vector。

答兩個就夠，最穩陣係 1 同 2，因為都可以直接指住文件入面嘅字。

RQ4 · PageRank

Graph：A → B, C, D；B → A, D；C → A；D → B, C。β = 0.8，N = 4，r⁽⁰⁾ = 1/4。

(a) 兩個問題同解決方法
問題一句定義例子
Dead endPage 冇 out-link，random surfer 去到就走唔出，importance 會「漏走」，總和唔再係 1。A → B，但 B 冇任何 link；iterate 落去所有 rank 趨向 0。
Spider trap一組 page 嘅 out-link 全部指返自己組入面，最終吸晒所有 importance。B → B（自己 link 自己），B 最後攞晒 1，其他 page 變 0。

解決方法：random teleport。每一步有 β 機率跟 link 行，1 − β 機率隨機跳去任何一頁：

$$r_j = \sum_{i \to j} \beta\,\frac{r_i}{d_i} + \frac{1-\beta}{N}$$

Spider trap：teleport 令 surfer 幾步之內就跳得出去。Dead end：去到 dead end 就一定 teleport（將嗰個 column 改成全部 1/N），咁 matrix 先係 column-stochastic。

(b)(i) Stochastic adjacency matrix M

規則：column = 由邊頁出發，row = 去邊頁。M[j][i] = 1 / out-degree(i)（如果 i → j）。每個 column 加埋 = 1。

function map(user, items):          # input: (user, list of items)

function reduce(pair, counts):       # input: ((item1, item2), [1, 1, ...])

MB2 · Spark DataFrame + UDF（12 分）

df_orders 有 order_id (Integer)、customer_id (String)、amount (Double)。(a) 寫 UDF size_tier(amount)：None 回傳 "Unknown"；≥ 500 "Large"；≥ 100 "Medium"；其他 "Small"。(b) 加 column tier，再計每個 tier 有幾多張單，按數量由多到少排。

睇答案
from pyspark.sql.functions import udf, col, count
from pyspark.sql.types import StringType

def size_tier(amount):
    if amount is None:
        return "Unknown"
    if amount >= 500:
        return "Large"
    if amount >= 100:
        return "Medium"
    return "Small"

tier_udf = udf(size_tier, StringType())

df_tier = df_orders.withColumn("tier", tier_udf(col("amount")))
result = (df_tier.groupBy("tier")
                 .agg(count("*").alias("n_orders"))
                 .orderBy(col("n_orders").desc()))
result.show()
  • 先處理 None，否則 None >= 500 會出錯。
  • 判斷次序由大到細：先 ≥ 500 再 ≥ 100，否則 600 會被當成 Medium。
  • Return type 係 StringType()，寫錯會出 null。
  • 都可以寫 df_tier.groupBy("tier").count().orderBy(col("count").desc())。
