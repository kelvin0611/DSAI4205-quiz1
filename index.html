相片 1 · In-class exercise（slide 67）：用 MapReduce 建 inverted index

同 DSAI4205 2025/26 Sem 1 期考 Q1(a)（10 分）一模一樣

To enable fast keyword search, build an inverted index that maps each word → list of document IDs where it appears. Please provide the pseudocode of one MapReduce job.

Example inputDesired output
D1 || the cat sat on the mat
D2 || a quick brown fox jumps
D3 || the quick brown fox
D4 || sat on the brown mat		 a: [D2] brown: [D2, D3, D4] cat: [D1] fox: [D2, D3] jumps: [D2] mat: [D1, D4] on: [D1, D4] quick: [D2, D3] sat: [D1, D4] the: [D1, D3, D4]

標準答案（老師喺相入面寫嘅版本）

function MAP(doc_id, document_text):
    words = trim(split(document_text, " "))      // 切成一粒粒字，順手去走前後空格
    for each word in words:
        emit(word, doc_id)                        // key = word, value = doc_id

function REDUCE(word, doc_ids_list):              // 收到時已經 group 好，例如 ("the", [D1, D1, D3, D4])
    doc_ids_list = doc_ids_list.removeDuplicates() // ★ 最多人漏：同一份文件可以出現同一個字兩次
    emit(word, doc_ids_list)                      // ("the", [D1, D3, D4])
階段邊個做InputOutput
MAP你寫(D1, "the cat sat on the mat")(the,D1) (cat,D1) … 每粒字一個 pair
SHUFFLE框架自動所有 mapper 嘅 output(the, [D1, D1, D3, D4]) 只係 group，唔會去重複
REDUCE你寫(word, doc_ids_list)(the, [D1, D3, D4])
易錯位（老師親口講）
  • key 揀錯：寫 emit(doc_id, word) 會令 shuffle 按 D1、D2 group，等於砌返原本份文件，冇用。要按「字」分組，key 就係 word。
  • 喺 reducer 寫 group by：grouping 係 shuffle 做嘅，reducer 收到嗰陣已經係 (key, list of values)。
  • 漏 removeDuplicates：「去年大部分同學 MAP 啱晒，REDUCE 就因為冇去重複而失分。」
  • 冇寫 trim 都有分：只要講清楚「split 成字 → 每個字 emit(word, doc_id)」就攞 MAP 全部分數。

另一個做法：喺 MAP 用 for each word in set(words)，每份文件每個字只 emit 一次，咁 reducer 就唔使去重複。兩種都啱，但考試寫老師版本最穩陣。

L3 Part 1–2

MapReduce：概念同答題模板

MapReduce 係 Google 喺 2004 年發明，第一個廣泛使用嘅分散式大數據框架。三大賣點：簡單嘅程式模型（只寫 map 同 reduce）、用平價硬件大規模擴展、內置 fault tolerance。數據模型：一個 file 就係一袋 (key, value) pair，input 同 output 都係 (key, value)，output 嘅 key 可有可無。

步驟做咩
1 · Map由每個 record／文件抽取資料，輸出 (key, value)
2 · Shuffle & Sort將 record 喺唔同機器之間搬，按 key 分組
3 · Reduceaggregate、summarize、filter 或 transform
4 · Write寫出結果。成個框架唔變，只係因應題目改 map 同 reduce function

課堂 word count 例子（slide 11）

map(String key, String value):          // key: document name, value: document contents
    for each word w in value:
        emitIntermediate(w, 1)

reduce(String key, Iterator values):    // key: a word, values: a list of counts
    sum = 0
    for each v in values:
        sum += v
    emit(key, sum)
Q1(a) 答題模板（4 步）
  1. 問自己：最後要「按咩分組」？答案就係 key。題目講 “in each department” → key = department；“for each word” → key = word。
  2. MAP：parse input → 如有條件就喺呢度 filter → emit(key, value)。
  3. Shuffle 唔使寫：框架自動變成 (key, [v1, v2, …])。可以喺 comment 寫低 reducer 會收到乜，示範你明。
  4. REDUCE：for each v in values → 加總／揀最大／去重複 → emit(key, result)。

MapReduce 嘅問題（點解要有 Spark）

  • 所有嘢都要用 mapper 同 reducer 表達，好 rigid（唔可以淨係有 mapper），複雜 query 要串好多個 MapReduce job。
  • 所有中間結果都寫落 disk（為咗 fault tolerance）。
  • 唔同 iteration／phase 之間只可以靠 shared storage 傳數據。
  • 因為 replication 同 disk I/O，所以慢。理想係經 memory 傳。
MapReduceSpark

程式模型得 map + reduce 兩步好多 transformation：map、filter、join、groupByKey…
Fault tolerance靠 replication + disk靠 lineage 重算失咗嘅 partition
最適合一次過嘅 batch jobiterative、互動分析、streaming
L3 Part 3–5

Spark 核心概念

Spark 係一個平行處理數據嘅框架，支援大規模處理、將數據放喺 memory、同埋喺 worker 之間分配資源。四個 feature：Fast processing（用 RDD）、In-memory computing、Flexible（Java、Scala、R、Python）、All-in-one（SQL、ML、可視化）。

Component用途考試關鍵字
Spark Core基礎引擎：memory management、fault tolerance、scheduling／distributing／monitoring jobs、同 storage 溝通內含 RDD
Spark SQLstructured 同 semi-structured 數據DataFrame API、Data Source API、CSV／JSON
Spark Streamingbatch 同 real-time streaming將 live stream 切成每 X 秒一批（最細 0.5 秒，latency 約 1 秒），每批當 RDD 處理
MLlib可擴展嘅機器學習clustering、classification
GraphX圖計算引擎graph ETL、EDA、graph computation

Spark 架構（master–worker）

RDD（Resilient Distributed Dataset）

RDD 係乜

  • Spark 最基本嘅數據結構
  • Immutable：改唔到，只可以由舊 RDD 整個新 RDD
  • Distributed / partitioned：分成 partition，喺唔同機器平行處理
  • 只可以用 coarse-grained、deterministic 嘅 transformation 建立（map、filter、join）

三個關鍵特性

  • Lazy evaluation：唔即刻執行，只喺 memory 起一棵 operator tree，要結果先計
  • Lineage：記錄由原始數據到結果嘅每一步
  • Fault recovery：partition 失咗就用 lineage 重算；冇出事就冇額外成本

Transformation vs Action（必考）

陷阱

reduceByKey 個名有 reduce，但佢回傳 RDD，所以係 transformation。Lecture slide 29 將 parallelize 都當 transformation（“four operations in two types”：parallelize、map、filter 係 T，collect 係 A）。

Lazy 嘅證明：spark.textFile('不存在.txt') 唔會出錯，去到 .collect() 先報錯。好處：Spark 可以睇晒成條鏈先執行，合併同 pipeline 步驟、減少重複處理，慳時間同運算資源。

Slide 29–31 例子：data = [("A",1), ("B",2), ("A",3), ("B",5)]，先 map 乘 2 再 filter key == 'A'，得 [('A', 2), ('A', 6)]。調轉做（先 filter 再 map）結果一樣但更快，因為 map 要處理嘅數據少咗。

L1 Big Data · L2 Parallelism 同 Dask

L1 · 乜嘢係 Big Data

冇清晰定義，可以理解為：人類理解唔到咁複雜、要多部電腦一齊處理、塞唔落一部電腦嘅 memory、要比 brute force 更好嘅演算法、維度好多、變化好快。點解而家先興：收集數據平、儲存平、平行運算平（cloud、cluster、GPU）。

V意思題目見到呢啲字就係佢課堂例子
Volume數據量petabytes、terabytes per hour、海量2022 年全球智能手機網絡訂戶約 64 億

L2 · Scale up vs Scale out

  • Moore's law：transistor 數量大約每 18–24 個月翻一倍。但因為 quantum tunneling 同散熱，單個 CPU 唔可能再每 18 個月快一倍。2005 年 Herb Sutter：“The Free Lunch Is Over”。Transistor 仍然增加，用嚟加多啲 core。
  • 處理大數據三條路：Data reduction（feature selection、dimensionality reduction、compression）；Efficient algorithm & data structure（indexing、tree、hashmap、graph）；將工作分派畀多個 processor／worker。
  • Multi-core：同一粒 chip 上有多個 core，用 shared memory（同一個地址喺所有 core 指向同一份數據），每個 core 有自己嘅 local state。
  • 挑戰：worker 加倍，throughput 唔會加倍，因為協調有 overhead（5 人 team vs 30 人 team）。
  • Bulk operations / Data parallelism：同一個指令、多份數據（same instructions, multiple data items），例如 df[df['A'] > 1] 可以每個 core 處理唔同行。

L2 · Sharding vs Replication、HDFS

Sharding／PartitioningReplication
做咩將數據集切細，分佈喺多個 node喺唔同 node 存同一份數據嘅多個副本
目的平行處理Fault tolerance（redundancy）、讀得快（scalability）
代價／細節Vertical = 按 table／column 切；Horizontal = 同一個 table 嘅 row 分去唔同 node要 synchronization 保持所有副本一致（consistency）
  • Horizontal partition 啱做：filtering df[df['A'] > 1]、projection df[['A','B']]、apply。唔啱：groupby('A').count()，要先重新排數據，令相同 A 嘅 row 喺同一個 partition。
  • 點樣分：Range（一段 key 對應一個 core ID）或者 Hashing：n 個 core，key k 放去 h(k) % n。
  • HDFS（最常用分散式檔案系統）：fixed-size partitioning、3-way replication、write-once read-many。

L2 · Dask

Dask 係 open-source Python library，令你可以平行運算，將 NumPy、Pandas 由一部機擴展到幾千 core 嘅 cluster。點解用：familiar interface（API 似 NumPy/Pandas，改少少 code）、scalability、flexibility（dask.delayed）、diagnostic tools（live dashboard 搵 bottleneck）。第一條規則：唔係乜都啱用；平行運算有 overhead，數據細就唔值。數據塞唔落 memory 或者要平行計先用。

睇答案
// (1) Map worker
// Input : key = row id (or file offset), value = (student_name, department, salary)
// Output: key = department, value = 1          e.g. (Computing, 1)
function MAP(row_id, row):
    (name, dept, salary) = parse(row)
    if salary > 25000:
        emit(dept, 1)

// (2) Reduce worker
// Input : key = department, value = list of 1s  e.g. (Computing, [1, 1])
// Output: key = department, value = total count  e.g. (Computing, 2)
function REDUCE(dept, counts):
    total = 0
    for each c in counts:
        total = total + c
    emit(dept, total)

題 2：一個好大嘅整數 file

Design MapReduce algorithms to take a very large file of integers and produce as output: (a) the largest integer; (b) the average of all the integers; (c) the same set of integers, but with each integer appearing only once; (d) the count of the number of distinct integers.

睇答案
// (a) Largest integer：全部用同一個 key，送去同一個 reducer
function MAP(key, n):
    emit("max", n)
function REDUCE(k, numbers):
    m = -infinity
    for each n in numbers:
        if n > m: m = n
    emit("max", m)

// (b) Average：value 要帶 (sum, count)
function MAP(key, n):
    emit("avg", (n, 1))
function REDUCE(k, pairs):
    total = 0; count = 0
    for each (s, c) in pairs:
        total = total + s
        count = count + c
    emit("avg", total / count)

// (c) Distinct：數字本身做 key，shuffle 自動將重複嘅 group 埋一齊
function MAP(key, n):
    emit(n, null)
function REDUCE(n, values):
    emit(n, null)                 // 每個 key 只會 emit 一次

// (d) Count distinct：要兩個 job
// Job 1 = (c)；Job 2：
function MAP(n, null):
    emit("count", 1)
function REDUCE(k, ones):
    emit("count", sum(ones))
  • (a) 得一個 key → 只有一個 reducer 做嘢，會變 bottleneck。改良：每個 map task 先計自己嗰份嘅最大值，先 emit 一個數（書入面叫 combiner）。
  • (b) 如果 mapper 先自己計平均，一定要送 (sum, count)，唔可以送平均值：[1,2,3] 平均 2、[10] 平均 10，「平均嘅平均」= 6，但真平均 = 16 ÷ 4 = 4。
  • (d) 一個 MapReduce job 做唔晒，要串兩個 job，呢個正正係 L3 講 MapReduce「too rigid」嘅例子。

概念短答

老師冇講 Q1(b) 問乜，只講「問概念，寫文字」。以下 8 題係 L3 最核心嘅概念，答案寫成考試可以直接用嘅英文，2–4 句就夠。

1. Transformation vs action；乜嘢係 lazy evaluation，有咩好處？

A transformation (e.g. map, filter, reduceByKey) creates a new RDD from an existing one. It is lazy: Spark only records it in the lineage / logical plan and does not execute it. An action (e.g. collect, count, take) returns a value to the driver and triggers the execution of all pending transformations. Lazy evaluation lets Spark see the whole chain first, so it can optimise it (merge and pipeline steps, skip unnecessary work), saving time and computing resources.

2. Narrow vs wide transformation，各舉一例；點解 wide 貴啲？

In a narrow transformation, each output partition is computed from a single input partition (e.g. map, filter), so no data needs to move between workers. In a wide transformation, an output partition needs data from many input partitions (e.g. groupByKey, reduceByKey, sortBy, join), so data must be shuffled across the network. The shuffle adds network I/O and latency and starts a new stage, so wide transformations are more expensive.

3. 點解 Spark 通常比 Hadoop MapReduce 快，尤其係 iterative job？

MapReduce writes all intermediate results to disk (with replication) and can only share data between jobs or iterations through shared storage, so every iteration pays disk I/O. Spark keeps RDDs in memory (and can cache RDDs that are reused), chains many transformations in one job, and gets fault tolerance from lineage instead of replicating intermediate data.

4. RDD 點做到 fault tolerance？worker 死同 driver 死有咩分別？

RDDs are immutable and remember their lineage, the deterministic transformations used to build them from the original data. If a worker fails, its lost partitions are recomputed from the original data using the lineage, and the driver reassigns the tasks to other workers, so the job continues. If the driver fails, the application's state is lost; there is no automatic recovery, so the application must be restarted from the beginning.

5. Inverted index MapReduce 入面，shuffle 做咗咩？點解 reducer 要去重複？

The shuffle phase collects all mapper outputs and groups them by key, sending all pairs with the same word to the same reducer as (word, [doc_ids]). It only groups; it does not remove duplicates. If a word appears twice in one document (e.g. “the” in D1), D1 appears twice in the list, so the reducer must remove duplicates before emitting the result.

6. map() 同 flatMap() 有咩分別？

map() produces exactly one output element for each input element, so splitting sentences gives one list per sentence (nested lists). flatMap() lets each input produce zero or more outputs and flattens them, so splitting sentences gives one flat RDD of words. Example: ['hello world', 'hi'] → map gives [['hello','world'], ['hi']]; flatMap gives ['hello','world','hi'].

7. Scale up vs scale out；點解大數據用 scale out？

Scale up (vertical) upgrades one machine with a faster CPU or more memory; scale out (horizontal) adds more machines or workers and distributes the work. Single-CPU clock speeds can no longer keep doubling because of physical limits (heat, quantum tunnelling), and one machine's memory is limited, so big data systems such as Hadoop, Dask and Spark scale out. Coordination overhead means doubling the workers does not double the throughput.

8. Sharding（partitioning）同 replication 有咩分別？

Sharding splits a dataset into smaller subsets, horizontally (rows) or vertically (columns or tables), stored on different nodes so they can be processed in parallel. Replication stores multiple copies of the same data on different nodes for fault tolerance and faster reads (HDFS keeps 3 copies), at the cost of keeping the replicas consistent.
